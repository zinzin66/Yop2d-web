How to make a brick breaker game?

Beginner guide · no code

Français · English

In a brick breaker, a ball bounces off the edges and off a paddle you move with your finger, and breaks bricks. Here we drive the ball with two small variables, vx (its speed to the right) and vy (its speed downward). When the ball bounces, we simply change the sign of the variable.

You need:
  • an Image named paddle, at the bottom of the screen (for example 208 x 48 px, around y = 1700);
  • an Image named ball, in the middle of the screen (for example 44 x 44 px);
  • bricks: Images at the top of the screen (for example 128 x 64 px, 8 per row);
  • two Text objects: scoreText (text “Score: 0”) and livesText (text “Lives: 3”), at the top of the screen.
👉 This guide is written for a 1080 x 1920 portrait game. The images come from Kenney's free Puzzle Pack (free to use, CC0), folder PNG/Double: paddleBlu.png (paddle, 208 x 48), ballBlue.png (ball, 44 x 44) and element_blue_rectangle_glossy.png (brick, 128 x 64, available in blue, green, red, yellow, purple and grey). You can also use your own drawings: then adapt the numbers in the formulas to their sizes.

Step 1: tags and variables

  1. Select a brick. In the inspector, field Tag (Label), type brick. Do the same for every brick.
  2. In the left panel, open the Variables section and create five variables, all with scope Local and type Integer:
  • score: starting value 0;
  • lives: starting value 3;
  • bricks: the number of bricks in your game (for example 27). It tells you when everything is broken;
  • vx and vy: starting value 0. This is the ball's speed, set when the game starts.
👉 One brick more or less? Just change the starting value of bricks. If the number is too big, you never win; if it is too small, you win too early.

Step 2: the paddle follows your finger

  1. Open the scene's Blueprint.
  2. Add the “Finger held down” event (it repeats as long as a finger is on the screen).
  3. Add “Move Object”: target paddle, X, value =clamp(doigt.x - 104, 0, 872), Y = 1700.
  4. Link the two nodes, then run the game: the paddle follows your finger and never leaves the screen.
Finger held down
→
Move Objectpaddle · =clamp(doigt.x - 104, 0, 872) · 1700
👉 How to read the formula? doigt.x is your finger's position (“doigt” means finger). We subtract 104 (half the paddle) to center it under the finger. clamp(…, 0, 840) keeps it on screen: 872 = 1080 − 208 (the paddle's width).

Step 3: the ball starts

  1. Add the “On Start” event, then two “Modify Variable” nodes one after the other: variable vx = 6, then variable vy = -9.
  2. Add the “Every frame” event, then “Push object”: target ball, Add X, value =vx, Add Y, value =vy.
  3. Link each event to its nodes and run the game: the ball goes up and to the right, and leaves the screen.
On Start
→

→
Modify Variablevy · -9

→
Push objectball · =vx · =vy
👉 Negative = up. In Yop2D, Y grows toward the bottom of the screen: vy = -9 sends the ball upward. For a faster ball, use 8 and -12.

Step 4: bounce on the edges

Right after “Push object”, we check on every frame whether the ball touches an edge. We chain three “Condition” nodes, each time following the “Then” output (which runs in every case).

  1. Left edge: “Condition” =ball.x <= 0. Output True → “Modify Variable”: variable vx, value =abs(vx) (always to the right).
  2. Right edge: “Condition” =ball.x >= 1036. Output True → “Modify Variable”: variable vx, value =-abs(vx) (always to the left). 1036 = 1080 − 44 (the ball's width).
  3. Top: “Condition” =ball.y <= 0. Output True → “Modify Variable”: variable vy, value =abs(vy) (always downward).
  4. Link each “Condition” to the next one with its “Then” output. The first one is linked to the output of “Push object”.

👉 Why abs? abs(vx) is always a positive number. At the left edge, the ball is forced to go right, even if it touches the edge two frames in a row: it never gets stuck.

Step 5: bounce on the paddle

  1. Add the “Collision A/B” event: Object A = ball, Object B = paddle.
  2. Add “Modify Variable”: variable vy, value =-abs(vy) (the ball goes back up).
  3. Add a second “Modify Variable”: variable vx, value =(ball.x + 22 - paddle.x - 104) / 13.
  4. Link the three nodes in order.
Collision A/Bball · paddle
→
Modify Variablevy · =-abs(vy)
→
Modify Variablevx · =(ball.x + 22 - paddle.x - 104) / 13
👉 What is the last formula for? It measures where the ball lands on the paddle: in the middle, it goes straight up; on the left edge, it goes left; on the right edge, it goes right. The player can aim. (22 = half the ball, 104 = half the paddle.)

Step 6: break the bricks

  1. Add the “If object touches Tag” event: target ball, Tag brick.
  2. Add “Destroy Object” and choose The object involved in the event as the target: it is the brick the ball has just touched.
  3. Add “Modify Variable”: variable vy, value =-vy (the ball bounces).
  4. Add “Add to Variable”: variable score, Value to add = 10.
  5. Add “Add to Variable”: variable bricks, Value to add = -1.
  6. Add “Modify Text”: target scoreText, New text, value ="Score: " + score.
  7. Link all the nodes in order.

👉 When the ball breaks a brick, it always bounces up or down, even if it hit the brick from the side. It is simple, and it works well in a brick breaker.

Step 7: win

After the “Modify Text” of step 6, add:

  1. “Condition” =bricks <= 0.
  2. On the True output: “Modify Variable” vx = 0, “Modify Variable” vy = 0 (the ball stops), then “Small message at the bottom of the screen” with the message You win!, then “Wait” 2 seconds, then “Restart the scene”.

👉 “Restart the scene” puts the objects back in place and the Local variables back to their starting value: the game restarts with 3 lives, 0 points and all the bricks.

Step 8: lives and Game Over

When the ball falls below the paddle, the player loses a life. We continue the chain from step 4: after the third “Condition” (the top), add a fourth one, linked by its “Then” output.

  1. “Condition” =ball.y >= 1920, output True.
  2. “Add to Variable”: variable lives, Value to add = -1.
  3. “Modify Text”: target livesText, New text, value ="Lives: " + lives.
  4. “Condition” =lives <= 0.
  5. Output True (no lives left): “Move Object” the ball to X = 518, Y = 1000, “Modify Variable” vx = 0, “Modify Variable” vy = 0 (the ball is put back in the middle and stops), then “Small message at the bottom of the screen” “Game over!”, “Wait” 2 seconds, “Restart the scene”.
  6. Output False (lives left): “Move Object” the ball to X = 518, Y = 1000, then “Modify Variable” vy = -9, then “Modify Variable” vx = 6.

Going further

  • Sounds: add “Play sound” after “Destroy Object” (a “clack” when a brick breaks) and in the paddle event.
  • Different colors: give the same tag brick to all the bricks, whatever their color: a single setup is enough.
  • More speed: add “Modify Variable” =vx * 1.02 each time a brick breaks so the game gets harder and harder.
  • Sparks: add an “Particle effect” when a brick breaks (see the guide Particles and effects).

If it doesn't work

  • The ball doesn't move: check that vx and vy are changed at the start, and that “Push object” uses the formulas =vx and =vy (with the = at the beginning).
  • The ball goes through the paddle or the bricks: check the names (ball, paddle) and the tag brick, spelled the same everywhere (no capital letter). If the ball is very fast, make the bricks a little bigger or slow the ball down.
  • The ball leaves the screen without bouncing: the “Condition” nodes must be linked one after the other with the “Then” output, and the first one must start from “Push object”.
  • You win too early or never: the variable bricks must be exactly the number of bricks in the game.
  • The paddle moves badly: in the formula, doigt.x is the finger, not the paddle; keep the = at the beginning and close the parenthesis.
