如何制作打砖块游戏？

新手教程 · 无需代码

Français · English · Español · Deutsch · Italiano · Português · Русский · 中文 · 日本語

在打砖块游戏中，球会在墙和你用手指移动的挡板上反弹，并打碎砖块。这里球靠两个变量移动：vx（向右的速度）和 vy（向下的速度）。球碰到墙时，我们只需给它另一个数字。

你需要：
  • 一个名为 paddle 的图像，放在屏幕下方（例如 208 x 48 px，大约在 y = 1700）；
  • 一个名为 ball 的图像，放在屏幕中间（例如 44 x 44 px）；
  • 砖块：屏幕上方的若干图像（例如 128 x 64 px，每行 8 个）；
  • 两个文本对象：scoreText（文字 “得分：0”）和 livesText（文字 “生命：3”），放在屏幕上方。
👉 本教程针对 1080 x 1920 竖屏游戏编写。图片来自免费素材包 Puzzle (brick breaker)（Kenney，可自由使用，CC0）。在 Yop2D 的资源库中打开可下载素材包标签页即可下载：里面有 paddleBlu（挡板）、ballBlue（球）和 element_blue_rectangle_glossy（砖块，有蓝、绿、红、黄、紫、灰色）。你也可以使用自己的图画。

第 1 步：标签和变量

  1. 选中一块砖。在检查器的 标签 (Tag) 栏中输入 brick。每块砖都这样做。
  2. 在左侧面板中打开 变量 部分，创建五个变量，范围都选 局部，类型都选 整数：
  • score：初始值 0；
  • lives：初始值 3；
  • bricks：你的游戏中的砖块数量（例如 24）。它用来判断砖块何时全部打碎；
  • vx 和 vy：初始值 0。这是球的速度，在游戏开始时设置。
👉 多一块或少一块砖？只需修改 bricks 的初始值。数字太大，永远赢不了；数字太小，会赢得太早。

第 2 步：看不见的墙

球会在看不见的墙上反弹：在屏幕四周放四个区域。区域在游戏中是看不见的，但球可以碰到它。

  1. 添加一个名为 left_wall 的区域：X = -300，Y = -400，宽 300，高 2800。
  2. 添加一个名为 right_wall 的区域：X = 1080，Y = -400，宽 300，高 2800。
  3. 添加一个名为 top_wall 的区域：X = -300，Y = -300，宽 1680，高 300。
  4. 添加一个名为 bottom_wall 的区域：X = -300，Y = 1920，宽 1680，高 300。
👉 墙故意做得很厚：快速的球穿不过去。前三面墙把球弹回去；bottom_wall 用来失去一条生命。

第 3 步：挡板跟随手指

  1. 选中 paddle，点击 ⚙ Comportement de l'objet，选择 用手指拖动：玩家可以抓住它并移动。
  2. 打开场景的蓝图，添加事件 “每帧”。
  3. 添加 “修改属性”：目标 paddle，属性 = y，值 = 1700。
  4. 添加 “保持在屏幕内”：目标 paddle，边距 = 0。
  5. 按顺序连接这三个节点。

👉 为什么要这两个节点？ “用手指拖动” 让挡板可以向任意方向移动。我们在每一帧把它放回同一高度，并防止它离开屏幕：这样它只会左右移动。

第 4 步：球出发

  1. 添加事件 “启动时”，然后依次添加两个 “修改变量” 节点：变量 vx，值 6，再是变量 vy，值 -9。
  2. 添加事件 “每帧”，然后添加 “推动对象”：目标 ball。
  3. 在 “推动对象” 的设置窗口中，点击 增加 X 旁边的 🔗 按钮，选择 “变量的值”，然后在出现的绿色节点中选择变量 vx。
  4. 对 增加 Y 做同样的事，选择变量 vy。
  5. 把每个事件连到它的节点，然后运行游戏：球向右上方飞去，然后飞出屏幕。
启动时
→
修改变量vx · 6
→
修改变量vy · -9
每帧
→
推动对象ball · X ← vx · Y ← vy
👉 绿色节点可以给一个设置赋值，不用输入任何东西。这里 “变量的值” 对 “推动对象” 说：“每一帧向右移动 vx，向下移动 vy”。
👉 负数 = 向上。 在 Yop2D 中，Y 朝屏幕下方增大：vy = -9 会让球向上飞。

第 5 步：在墙上反弹

每面墙都会给球一个新的数字。添加三个 “碰撞 A/B” 事件（对象 A = ball）：

  1. 对象 B = left_wall → “修改变量”：变量 vx，值 6（球回到向右飞）。
  2. 对象 B = right_wall → “修改变量”：变量 vx，值 -6（球回到向左飞）。
  3. 对象 B = top_wall → “修改变量”：变量 vy，值 9（球回到向下飞）。

第 6 步：在挡板上反弹

  1. 添加事件 “碰撞 A/B”：对象 A = ball，对象 B = paddle。
  2. 添加 “修改变量”：变量 vy，值 -9（球重新向上飞）。
  3. 再添加一个 “修改变量”：变量 vx。点击值旁边的 🔗，选择 “随机数”，然后设置 从 = -6，到 = 6。
  4. 按顺序连接这些节点。

→
修改变量vy · -9

修改变量vx · ← 随机数（-6 到 6）
👉 每次在挡板上反弹，球都会朝随机方向飞出：游戏永远不会两次一样。

第 7 步：打碎砖块

  1. 添加事件 “如果对象碰到标签”：目标 ball，标签 brick。
  2. 添加 “销毁对象”，并选择 事件中涉及的对象 作为目标：它就是球刚刚碰到的那块砖。
  3. 添加 “条件” =vy < 0（“球正在向上飞”）。输出 真 → “修改变量”：变量 vy，值 9。输出 假 → “修改变量”：变量 vy，值 -9。
  4. 从条件的 “然后” 输出开始，添加 “增加变量值”：变量 score，要增加的值 = 10。
  5. 添加 “增加变量值”：变量 bricks，要增加的值 = -1。
  6. 添加 “修改文本”：目标 scoreText，新文本 = ="得分：" + score。

👉 为什么用 =vy < 0？ 如果 vy 小于 0，球正在向上飞：打碎砖块后，它向下飞。否则它正在向下飞，然后再向上飞。
👉 文字开头的 = 号告诉 Yop2D 去计算这段文字，而不是原样写出来（参见教程收集金币并计分）。

第 8 步：获胜

在第 7 步的 “修改文本” 之后，添加：

  1. “条件” =bricks <= 0.
  2. 在 真 输出上：“修改变量” vx = 0，“修改变量” vy = 0（球停下），然后 “屏幕底部小提示” 显示消息 你赢了！，再 “等待” 2 秒，最后 “重新开始场景”。

👉 “重新开始场景” 会让对象回到原位，并让 局部 变量恢复初始值：游戏重新开始，有 3 条生命、0 分和全部砖块。

第 9 步：生命和 Game Over

球碰到 bottom_wall（屏幕下方）时，玩家失去一条生命。

  1. 添加事件 “碰撞 A/B”：对象 A = ball，对象 B = bottom_wall。
  2. “增加变量值”：变量 lives，要增加的值 = -1。
  3. “修改文本”：目标 livesText，新文本 = ="生命：" + lives。
  4. “条件” =lives <= 0.
  5. 输出 真（没有生命了）：“移动对象” ball 到 X = 518，Y = 1000，“修改变量” vx = 0，“修改变量” vy = 0（球回到中间并停下），然后 “屏幕底部小提示” “游戏结束！”，“等待” 2 秒，“重新开始场景”。
  6. 输出 假（还有生命）：“移动对象” ball 到 X = 518，Y = 1000，然后 “修改变量” vy = -9，再 “修改变量” vx = 6。

👉 为什么等待之前要先让球停下？ 在 2 秒的等待期间，游戏仍在运行。如果球一直停在屏幕下方，它每一帧都会扣掉一条生命，生命计数会降到很低。把它放回中间并让它静止，就不会再捣乱了。

进一步改进

  • 声音：在 “销毁对象” 之后添加 “播放音效”（砖块碎裂时发出「啪」的一声），也可以加在挡板的事件里。
  • 不同颜色：不管颜色如何，给所有砖块相同的标签 brick：一套设置就够了。
  • 更快的球：把所有地方的数字 6、-6、9 和 -9 都改掉（例如改成 8、-8、12 和 -12）。
  • 火花：砖块碎裂时添加一个 “粒子效果”（参见教程粒子与特效）。

如果不起作用

  • 球不动：检查 vx 和 vy 是否在开始时被修改，以及 “推动对象” 是否连接到绿色的 “变量的值” 节点（点击 增加 X：那一行应该显示绿色的线）。
  • 球穿过墙或砖块：检查名称（ball、paddle、left_wall……）和标签 brick，每处写法要一致（不要大写）。如果球太快，把砖块做大一点，或者让球慢一点。
  • 挡板向上或向下跑：节点 “修改属性” 必须连接到 每帧，并且 属性 = y。
  • 赢得太早或永远赢不了：变量 bricks 必须正好等于游戏中的砖块数量。
  • 想对照一下，可以打开测试项目（它的节点按部分整理，带有框和便利贴，解释每一部分）。
