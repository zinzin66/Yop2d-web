如何制作打砖块游戏？

新手教程 · 无需代码

Français · English · Español · Deutsch · Italiano · Português · Русский · 中文 · 日本語

在打砖块游戏中，球会在边缘和你用手指移动的挡板上反弹，并打碎砖块。这里我们用两个小变量来控制球：vx（向右的速度）和 vy（向下的速度）。球反弹时，我们只需改变变量的正负号。

你需要：
  • 一个名为 paddle 的图像，放在屏幕下方（例如 208 x 48 px，大约在 y = 1700）；
  • 一个名为 ball 的图像，放在屏幕中间（例如 44 x 44 px）；
  • 砖块：屏幕上方的若干图像（例如 128 x 64 px，每行 8 个）；
  • 两个文本对象：scoreText（文字 “得分：0”）和 livesText（文字 “生命：3”），放在屏幕上方。
👉 本教程针对 1080 x 1920 竖屏游戏编写。图片来自免费素材包 Puzzle (brick breaker)（Kenney，可自由使用，CC0）。在 Yop2D 的资源库中打开可下载素材包标签页即可下载：里面有 paddleBlu（挡板，208 x 48）、ballBlue（球，44 x 44）和 element_blue_rectangle_glossy（砖块，128 x 64，有蓝、绿、红、黄、紫、灰色）。你也可以使用自己的图画：这时请按它们的尺寸调整公式中的数字。

第 1 步：标签和变量

  1. 选中一块砖。在检查器的 标签 (Tag) 栏中输入 brick。每块砖都这样做。
  2. 在左侧面板中打开 变量 部分，创建五个变量，范围都选 局部，类型都选 整数：
  • score：初始值 0；
  • lives：初始值 3；
  • bricks：你的游戏中的砖块数量（例如 27）。它用来判断砖块何时全部打碎；
  • vx 和 vy：初始值 0。这是球的速度，在游戏开始时设置。
👉 多一块或少一块砖？只需修改 bricks 的初始值。数字太大，永远赢不了；数字太小，会赢得太早。

第 2 步：挡板跟随手指

  1. 打开场景的蓝图。
  2. 添加事件 “手指按住”（只要屏幕上有手指，它就会不断重复）。
  3. 添加 “移动对象”：目标 paddle，X = =clamp(doigt.x - 104, 0, 872)，Y = 1700。
  4. 连接这两个节点，然后运行游戏：挡板会跟着你的手指，并且不会离开屏幕。
手指按住
→
移动对象paddle · =clamp(doigt.x - 104, 0, 872) · 1700
👉 如何读这个公式？ doigt.x 是你手指的位置（“doigt” 在法语中是手指的意思）。我们减去 104（挡板宽度的一半），让挡板位于手指正下方。clamp(…, 0, 872) 让它保持在屏幕内：872 = 1080 − 208（挡板的宽度）。

第 3 步：球出发

  1. 添加事件 “启动时”，然后依次添加两个 “修改变量” 节点：变量 vx = 6，再是变量 vy = -9。
  2. 添加事件 “每帧”，然后添加 “推动对象”：目标 ball，增加 X = =vx，增加 Y = =vy。
  3. 把每个事件连到它的节点，然后运行游戏：球向右上方飞去，然后飞出屏幕。
启动时
→
修改变量vx · 6
→
修改变量vy · -9
每帧
→
推动对象ball · =vx · =vy
👉 负数 = 向上。 在 Yop2D 中，Y 朝屏幕下方增大：vy = -9 会让球向上飞。想要更快的球，可以用 8 和 -12。

第 4 步：在边缘反弹

紧接着 “推动对象”，我们在每一帧检查球是否碰到边缘。我们把三个 “条件” 节点串起来，每次都沿着 “然后” 输出连接（它在任何情况下都会执行）。

  1. 左边缘：“条件” =ball.x <= 0。输出 真 → “修改变量”：变量 vx，值 =abs(vx)（始终向右）。
  2. 右边缘：“条件” =ball.x >= 1036。输出 真 → “修改变量”：变量 vx，值 =-abs(vx)（始终向左）。1036 = 1080 − 44（球的宽度）。
  3. 上边缘：“条件” =ball.y <= 0。输出 真 → “修改变量”：变量 vy，值 =abs(vy)（始终向下）。
  4. 用每个 “条件” 的 “然后” 输出连接到下一个。第一个连接到 “推动对象” 的输出。
推动对象ball
→
条件=ball.x <= 0
真 →
修改变量vx · =abs(vx)
条件=ball.x >= 1036
真 →
修改变量vx · =-abs(vx)
条件=ball.y <= 0
真 →
修改变量vy · =abs(vy)
👉 为什么用 abs？ abs(vx) 总是正数。在左边缘，球被强制向右飞，即使它连续两帧碰到边缘，也不会被卡住。

第 5 步：在挡板上反弹

  1. 添加事件 “碰撞 A/B”：对象 A = ball，对象 B = paddle。
  2. 添加 “修改变量”：变量 vy，值 =-abs(vy)（球重新向上飞）。
  3. 再添加一个 “修改变量”：变量 vx，值 =(ball.x + 22 - paddle.x - 104) / 13。
  4. 按顺序连接这三个节点。
碰撞 A/Bball · paddle
→
修改变量vy · =-abs(vy)
→
修改变量vx · =(ball.x + 22 - paddle.x - 104) / 13
👉 最后一个公式有什么用？ 它测量球落在挡板的哪个位置：落在中间时直直向上；落在左边时向左飞；落在右边时向右飞。这样玩家就可以瞄准。（22 = 球宽度的一半，104 = 挡板宽度的一半。）

第 6 步：打碎砖块

  1. 添加事件 “如果对象碰到标签”：目标 ball，标签 brick。
  2. 添加 “销毁对象”，并选择 事件中涉及的对象 作为目标：它就是球刚刚碰到的那块砖。
  3. 添加 “修改变量”：变量 vy，值 =-vy（球反弹）。
  4. 添加 “增加变量值”：变量 score，要增加的值 = 10。
  5. 添加 “增加变量值”：变量 bricks，要增加的值 = -1。
  6. 添加 “修改文本”：目标 scoreText，新文本 = ="得分：" + score。
  7. 按顺序连接所有节点。

👉 球打碎砖块时，总是向上或向下反弹，即使它是从侧面碰到砖块的。这样做很简单，在打砖块游戏中效果也很好。

第 7 步：获胜

在第 6 步的 “修改文本” 之后，添加：

  1. “条件” =bricks <= 0.
  2. 在 真 输出上：“修改变量” vx = 0，“修改变量” vy = 0（球停下），然后 “屏幕底部小提示” 显示消息 你赢了！，再 “等待” 2 秒，最后 “重新开始场景”。

👉 “重新开始场景” 会让对象回到原位，并让 局部 变量恢复初始值：游戏重新开始，有 3 条生命、0 分和全部砖块。

第 8 步：生命和 Game Over

球掉到挡板下方时，玩家失去一条生命。我们延续第 4 步的链条：在第三个 “条件”（上边缘）之后，再添加第四个，用它的 “然后” 输出连接。

  1. “条件” =ball.y >= 1920，输出 真。
  2. “增加变量值”：变量 lives，要增加的值 = -1。
  3. “修改文本”：目标 livesText，新文本 = ="生命：" + lives。
  4. “条件” =lives <= 0.
  5. 输出 真（没有生命了）：“移动对象” ball 到 X = 518，Y = 1000，“修改变量” vx = 0，“修改变量” vy = 0（球回到中间并停下），然后 “屏幕底部小提示” “游戏结束！”，“等待” 2 秒，“重新开始场景”。
  6. 输出 假（还有生命）：“移动对象” ball 到 X = 518，Y = 1000，然后 “修改变量” vy = -9，再 “修改变量” vx = 6。

👉 为什么等待之前要先让球停下？ 在 2 秒的等待期间，游戏仍在运行。如果球一直停在屏幕下方，它每一帧都会扣掉一条生命，生命计数会降到很低（-178！）。把它放回中间并让它静止，就不会再捣乱了。

进一步改进

  • 声音：在 “销毁对象” 之后添加 “播放音效”（砖块碎裂时发出「啪」的一声），也可以加在挡板的事件里。
  • 不同颜色：不管颜色如何，给所有砖块相同的标签 brick：一套设置就够了。
  • 更快的速度：每打碎一块砖就添加 “修改变量” =vx * 1.02，让游戏越来越难。
  • 火花：砖块碎裂时添加一个 “粒子效果”（参见教程粒子与特效）。

如果不起作用

  • 球不动：检查 vx 和 vy 是否在开始时被修改，以及 “推动对象” 是否使用了公式 =vx 和 =vy（开头要有 =）。
  • 球穿过挡板或砖块：检查名称（ball、paddle）和标签 brick，每处写法要一致（不要大写）。如果球太快，把砖块做大一点，或者让球慢一点。
  • 球没有反弹就飞出屏幕：各个 “条件” 节点必须通过 “然后” 输出一个接一个连接，并且第一个必须从 “推动对象” 出发。
  • 赢得太早或永远赢不了：变量 bricks 必须正好等于游戏中的砖块数量。
  • 挡板移动不正常：公式中的 doigt.x 是手指，不是挡板；开头要保留 =，并且括号要闭合。
